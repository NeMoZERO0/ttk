# Карта пространства

Сервис для навигации внутри зданий и на площадках мероприятий: организатор размечает 2D-план, ставит точки и панорамы, посетитель смотрит карту с телефона, строит маршрут и заранее проходит его по панорамам.

- Бэкенд — FastAPI (`app/`).
- Фронтенд — React + Vite + Tailwind CSS (`frontend/`).
- Экран посетителя — `http://localhost:5173`.
- Редактор организатора — `http://localhost:5173/editor`, демо-доступ `demo@space-map.app` / `demo123`.

## Что нужно установить один раз

- **Docker Desktop** — для PostgreSQL, Redis и MinIO.
- **Node.js 20.19+ или 22.12+** — проверить командой `node -v`.
- Python-окружение `.venv` уже есть в папке проекта.

## Запуск (Windows, PowerShell)

Понадобятся три окна терминала. В каждом сначала перейдите в папку проекта:

```powershell
cd $HOME\Desktop\space-map
```

**Терминал 1 — базы данных:**

```powershell
docker compose up -d
```

**Терминал 2 — бэкенд** (первая строка нужна только один раз):
Создать .venv
python -m venv .venv
.venv\Scripts\Activate.ps1
```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

При первом старте API само создаёт таблицы и демо-карту «Учебный корпус «А»»: 2 этажа, помещения и коридоры. Панорам в демо нет — добавьте их в редакторе (вкладка «Панорамы»): снимите на телефон или загрузите готовую. Проверка: http://localhost:8000/health. Документация API: http://localhost:8000/docs.

**Терминал 3 — фронтенд:**

```powershell
cd frontend
npm install
npm run dev
```

Откройте **http://localhost:5173**.

### С телефона

Телефон и компьютер должны быть в одной Wi-Fi сети. Vite при запуске печатает строку `Network: http://192.168.x.x:5173` — откройте этот адрес на телефоне. Если не открывается, разрешите Node.js в брандмауэре Windows.

Пошаговая съёмка панорамы работает и так: камера открывается через системное окно съёмки, HTTPS для этого не нужен.

### Работа без интернета

В режиме `npm run dev` офлайн отключён: он мешает горячей перезагрузке. Чтобы проверить офлайн-режим, соберите фронтенд:

```powershell
cd frontend
npm run build
npm run preview
```

Откройте http://localhost:4173 и нажмите внизу панели «Сохранить карту для работы без интернета». После этого карта, маршруты по уже открытым данным и все панорамы открываются без сети.

### Вариант: бэкенд в Docker

Вместо терминала 2 можно выполнить `docker compose --profile full up --build`. Порт 8000 должен быть свободен.

## Что сделано по требованиям кейса

| Требование | Где |
|---|---|
| Организатор рисует 2D-план, размечает комнаты и коридоры | Редактор → «Помещения»: перетаскивание, изменение размеров, площадь в м², этажи, габариты здания |
| Загрузить готовый план в редактор | «Помещения» → «Загрузить план (PNG, JPG)»: картинка ложится подложкой, по ней обводятся помещения |
| Стенды, залы, входы, стойки, Wi-Fi и любые места: название, категория, описание | Редактор → «Точки» (помещения тоже являются местами) |
| Точки видны на 2D-плане и в панорамах | Направление на каждое место вычисляется из плана, поэтому метки в панораме появляются сами. Ручные метки — в настройке панорамы |
| Редактировать, добавлять, удалять; изменения обновляют опубликованную карту без смены ссылки | Всё сохраняется автоматически; ссылка `/?map=<slug>` постоянная |
| Съёмка панорамы телефоном с подсказками порядка | «Панорамы» → «Добавить панораму» → «Снять на телефон»: 8 или 12 кадров, круг-подсказка, угол поворота (по компасу, если он есть), советы по съёмке |
| Сервис объединяет кадры в панораму | Склейка в браузере (`frontend/src/lib/stitch.js`): выравнивание кадров, автоподбор угла обзора камеры, выравнивание яркости, плавные швы |
| Загрузить готовую панораму | «Загрузить готовую»: 360° (2:1) или полоса из режима «Панорама» телефона |
| Привязать панораму к месту на плане, разместить на ней точки | Значок камеры перетаскивается по плану. В «Совместить с планом и метки» — поворот по ориентиру и ручные метки |
| Посетитель вращает обзор, открывает описания, переходит между панорамами | Просмотрщик на WebGL: мышь, палец, щипок, стрелки; метки мест и стрелки к соседним панорамам |
| Маршрут внутри здания или по территории, показ на 2D-плане | «Построить маршрут». Тип помещения «Территория» — проходимая зона снаружи |
| Пройти маршрут заранее по панорамам | После построения маршрута — кнопка «Пройти маршрут в панорамах» (шаги «Назад / Дальше») |
| Публикация по ссылке и встраивание в сайт | Редактор → «Публикация»: ссылка и код `<iframe>` (режим `&embed=1`) |
| Разделение функционала посетителя и организатора, защита доступа | Посетителю доступны только публичные ручки `/public/*`. Всё изменяющее требует JWT и проверяет владельца карты |
| Удобство с телефона, скорость загрузки | Адаптивная вёрстка. Панорама сначала грузится превью 1024 px, затем полная 4096 px. Файлы кешируются навсегда (уникальные имена) |
| Доп. идеи: несколько этажей, офлайн, статистика | Этажи и переходы по лестнице и лифту; офлайн через service worker; статистика просмотров, мест, маршрутов и панорам в «Публикации» |

## API (основное)

Публичное API (без входа):

| Метод | URL | Что делает |
|---|---|---|
| GET | `/public/maps` | опубликованные карты |
| GET | `/public/maps/{slug}` | карта: этажи, помещения, точки, панорамы с метками |
| POST | `/public/maps/{slug}/route` | маршрут `{from_node_id, to_node_id}` |
| POST | `/public/maps/{slug}/events` | событие статистики `{kind: view\|poi\|route\|pano}` |
| GET | `/files/{key}` | файлы планов и панорам |

Для организатора нужен заголовок `Authorization: Bearer <токен из /auth/login>`:

| Метод | URL | Что делает |
|---|---|---|
| POST | `/public/maps/{slug}/publish` | публикация (только владелец) |
| GET, PUT | `/maps/{id}/building` | габариты здания, м |
| GET, POST, PATCH, DELETE | `/maps/{id}/rooms[/{room_id}]` | помещения (с площадью `area_m2`) |
| GET, POST, PATCH, DELETE | `/maps/{id}/nodes[/{node_id}]` | точки |
| POST, DELETE | `/maps/{id}/floors/{floor_id}/plan[/upload]` | картинка готового плана |
| GET | `/maps/{id}/panoramas` | панорамы карты |
| POST | `/maps/{id}/panoramas/upload` | загрузка (multipart: `file, floor_id, x, y, name, hfov`) |
| PATCH, DELETE | `/maps/{id}/panoramas/{pano_id}` | имя, положение, направление `yaw` |
| POST, PATCH, DELETE | `/maps/{id}/panoramas/{pano_id}/hotspots[/{id}]` | метки на панораме |
| GET | `/maps/{id}/stats` | статистика |

## Как устроено

- **Координаты** помещений и точек хранятся в долях от габаритов здания (0..1), габариты — в метрах в `Map.settings`. Площадь помещения = `w × ширина × h × глубина`.
- **Маршруты.** Граф строится автоматически (`app/services/floorplan.py`):
  - на осевых линиях коридоров и «Территорий» ставятся узлы напротив каждой точки;
  - соприкасающиеся коридоры соединяются между собой;
  - лестницы и лифты соседних этажей связываются.

  Этажи без коридоров не трогаются: там остаётся граф, собранный вручную через `/nodes` и `/edges`.
- **Панорама** — равнопромежуточное изображение 2:1. Её положение задаёт точка `type="viewpoint"` на плане, `yaw` — направление «вверх по плану».
- **Файлы** пишутся в MinIO. Если он недоступен — в локальную папку `media/` (переменная `MEDIA_DIR`), поэтому сервис работает и без MinIO. Отдаются через `/files/...` с кешированием.
- **Таблицы** создаются при старте через `create_all`: миграция alembic в репозитории пустая. Отключается `AUTO_CREATE_TABLES=false`, демо-данные — `SEED_DEMO=false`.

## Безопасность

- Публикация и все изменения — только владельцем карты.
- Исправлено:
  - публикация без входа (раньше могла кто угодно);
  - удаление чужих точек и рёбер по id.
- Загрузки ограничены 25 МБ, проверяется, что это изображение. Файлы отдаются только из папок `plans/` и `panoramas/`.
- Перед выкладкой смените `JWT_SECRET` в `.env`.

## Частые проблемы

- **«Сервер карты не отвечает»** — не запущен бэкенд (терминал 2) или он упал. Ошибка видна в его окне.
- **`connection refused` к 5432** — не запущен Docker или контейнер `db`.
- **Образ Docker не скачивается** — можно указать зеркало, например `mirror.gcr.io/library/postgres:15`.
- **Панорама чёрная или не крутится** — в браузере выключен WebGL. Тогда показывается плоская картинка с прокруткой.
